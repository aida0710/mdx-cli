# トラブルシューティング

## mdxコマンドが見つからない

ターミナルを開き直し、インストール先がPATHに含まれているか確認します。macOS / Linuxの一般ユーザーでは `~/.local/bin`、Windowsでは `%LOCALAPPDATA%\Programs\mdx` が既定の配置先です。[インストール](install.html)も参照してください。

## ログインできない・接続がタイムアウトする

`oprpl.mdx.jp` と `mdxidm.mdx.jp` に接続できるか確認してください。学認経由のログインは未対応です。

```bash
mdx auth status
mdx auth login
```

OTPが拒否される場合は、端末と認証アプリの時刻、ログイン対象アカウントを確認します。別ユーザーに切り替える場合は、ログアウト後にログインし直してください。ログアウトすると保存済み認証情報も削除されます。

## 違うプロジェクトのVMが表示される

```bash
mdx project list
mdx project select
mdx vm list
```

一度だけ明示する場合は、対象コマンドに `--project-id` を付けます。

```bash
mdx vm list --project-id YOUR_PROJECT_ID
```

## Web / IPMIコンソールで入力が失敗する

一部のコンソールは対話入力で使う端末制御に対応していません。通常のSSHターミナルから実行してください。TOTPシークレットの登録には非対話入力もありますが、ログイン全体を非対話にする指定ではありません。[ログインと認証](auth.html)で入力方法を確認できます。

## 一括操作の対象が想定と異なる

`"worker-*"` のようにパターンを引用符で囲んでください。引用符がないと、CLIに渡る前にシェルがローカルのファイル名として展開することがあります。削除や構成変更の前に、対象VMを確認してください。

## 利用できるオプションを確認する

```bash
mdx --help
mdx vm deploy --help
mdx network check-acl --help
```

インストール済みバージョンのヘルプを確認してください。問題を共有するときは `mdx --version`、実行したコマンド、エラーメッセージを添え、パスワード・OTP・トークンは含めないでください。
